# Architecture — the static-site generator

**Purpose:** `build.mjs` is a zero-dependency Node generator that turns JSON string catalogs + HTML templates into the static HTML GitHub Pages serves. One flat URL per page, both languages baked into each file.

## Flow

```
i18n/<lang>/common.json   ┐
i18n/<lang>/<page>.json    ├─▶  build.mjs (render)  ─▶  <page>.html  (en + he in one file)
templates/partials/*.html  │
templates/pages/*.html    ┘
```

For every page in the registry, `build.mjs` renders the body template **once per language** (`en`, `he`), wraps each render in a `<div class="lang-block" data-lang-block="…">`, prepends a shared `<head>`, and writes one file. English is the baked default (crawlers / no-JS); a `<head>` script swaps to the visitor's language before first paint.

## Page registry (`PAGES` in build.mjs)

Each entry: `i18n` (catalog namespace) · `tpl` (body template) · `out` (file) · `url` (canonical path).

| i18n | tpl | out | url |
|------|-----|-----|-----|
| `home` | `home` | `index.html` | `/` |
| `privacy` | `legal` | `privacy.html` | `/privacy.html` |
| `terms` | `legal` | `terms.html` | `/terms.html` |
| `guidelines` | `legal` | `guidelines.html` | `/guidelines.html` |
| `support` | `support` | `support.html` | `/support.html` |

Templates are de-duped: `legal` is loaded once and reused by three pages. Add a page → add a `PAGES` entry (see [i18n.md](i18n.md)).

## Templates

- **Partials** (`templates/partials/`): `head.html`, `nav.html`, `footer.html` — reusable chrome, inlined via `{{partial:…}}`.
- **Pages** (`templates/pages/`): `home.html`, `legal.html`, `support.html` — body shapes (nav + `<main>` + footer, no `<head>`).

## Token system (`render()`)

`render(tpl, ctx)` does five ordered regex passes over a template string:

| Token | Expands to |
|-------|-----------|
| `{{partial:name}}` | the partial file `partials[name]` (nav / footer) |
| `{{sections}}` | the page catalog's `sections[]` → `<section class="prose__block">` blocks (optional `id`, `heading`) |
| `{{faq}}` | the page catalog's `faq[]` → `<details class="faq">` blocks (optional `id`) |
| `{{t:ns.key}}` | a translation, dotted lookup in the merged catalog (`common` + page namespace) |
| `{{var:name}}` | a computed per-page/per-language value (see below) |

`lookup()` warns `! missing string: <path>` and returns `""` on a missing key — the build never throws.

### Computed `vars`

Per language block: `lang`, `dir` (`ltr`/`rtl`), `idSuffix` (`-en`/`-he`), `h1`, `updated`, `intro` (raw HTML from the catalog; only guidelines defines it), `homeUrl` (`/`), `otherLang`, `otherLangLabel`, `otherLangParam` (`?lang=…`), `year`.
Per `<head>` (English only): `title`, `description`, `canonical`, `ogUrl`, `hreflang` (3 `<link rel="alternate">`), `i18nMeta` (a `<script id="i18n-meta">` JSON blob of each language's title/dir, used by the bootstrap to set `document.title`).

## Single-flat-URL, both-languages model

No `/en/` or `/he/` directories — one file per page holds both language blocks. CSS hides the inactive block:

```css
[data-lang-block="he"] { display: none; }          /* default = English */
html[data-lang="he"] [data-lang-block="en"] { display: none; }
html[data-lang="he"] [data-lang-block="he"] { display: block; }
```

The `<head>` bootstrap (`templates/partials/head.html`) runs synchronously before paint: applies saved theme, resolves language (`?lang=` > `localStorage` > `navigator.language` > `en`), sets `data-lang`/`lang`/`dir` on `<html>`, persists + strips `?lang=`, and sets the title. No flash, no reload. Details in [i18n.md](i18n.md). `build.mjs` also `rmSync`s a legacy `he/` directory each run (cleanup from the old per-language scheme).

## Generated vs hand-edited

| Generated by `build.mjs` (never hand-edit) | Hand-edited (functional tools / infra) |
|---|---|
| `index.html`, `privacy.html`, `terms.html`, `guidelines.html`, `support.html` | `promote.html`, `analytics.html`, `go/index.html`, `i/index.html`, `404.html`, `.well-known/*`, `CNAME`, `.nojekyll`, `ic_motify.svg` |

Edit generated pages via their catalogs + templates, then re-run `node build.mjs`. The redirect/deep-link infra is covered in [deployment.md](deployment.md).

## Run

```bash
node build.mjs        # regenerates all pages; prints ✓ per file
```

Commit the regenerated HTML alongside the source change — GitHub Pages serves the static files directly, no build in the hosting path ([deployment.md](deployment.md)).
