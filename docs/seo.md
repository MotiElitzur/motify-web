# SEO & AI search

How motify.uk is set up for search engines and AI answer engines, and how much it matters.

## Relevance (read first)

Motify's acquisition is App Store / Play (ASO) + proximity + referral deep-links. **Web search is a secondary channel**, so this is deliberately the cheap, one-time fundamentals — not an ongoing content-SEO program. The home page is worth ranking for brand + "meet people nearby" queries; the policy pages exist for store compliance, not search traffic.

## What's in place

| Item | Where | Notes |
|------|-------|-------|
| `robots.txt` | root, static | Allows all, points to the sitemap |
| `sitemap.xml` | **auto-generated by `build.mjs`** | 5 flat URLs, each with `hreflang` alternates for `?lang=en/he/x-default` + `lastmod` |
| Structured data (JSON-LD) | **auto-generated by `build.mjs`** (`buildJsonLd`) | `Organization` + `WebSite` sitewide; `SoftwareApplication` on home; `FAQPage` on support (built from the `faq` catalog) |
| Favicons + PWA | `assets/img/icon-*.png`, `apple-touch-icon.png`, `site.webmanifest` | Sourced from `assets/img/icon.html` (rendered via headless Chrome; see below) |
| Open Graph + Twitter | head partial + `assets/img/og.png` | `summary_large_image` card, 1200×630 |
| Fundamentals | head partial + templates | Unique `<title>`/description, `canonical`, `hreflang`, semantic HTML, one `<h1>`/block, alt text, mobile, fast static |

Regenerate icons / OG after a logo change:

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless=new --disable-gpu --force-device-scale-factor=1 --screenshot=assets/img/icon-512.png --window-size=512,512 "file://$(pwd)/assets/img/icon.html"
for s in 192 180 32 16; do cp assets/img/icon-512.png assets/img/icon-$s.png; sips -z $s $s assets/img/icon-$s.png; done
cp assets/img/icon-180.png assets/img/apple-touch-icon.png
"$CHROME" --headless=new --disable-gpu --force-device-scale-factor=1 --screenshot=assets/img/og.png --window-size=1200,630 "file://$(pwd)/assets/img/og.html"
```

## AI search ("AI SEO")

Google's 2026 guidance is explicit: *optimizing for generative AI search is still SEO* — no special schema, chunking, or `llms.txt` is required for Google's AI Overviews. The one real lever is **structured data** (already generated above), which lets Google, ChatGPT, Perplexity, and Bing Copilot verify entities and cite the site with confidence.

`llms.txt` (root) is included as a curated map for third-party LLMs (Perplexity may use it). Google has stated it has **no effect** on Google Search — keep it because it's cheap, don't expect ranking impact.

## The i18n ↔ SEO tradeoff

The site serves both languages from one URL (English baked, Hebrew hidden via CSS, chosen at runtime by `?lang=`; see [i18n.md](i18n.md)). Consequence: **Google indexes English well, Hebrew barely** (hidden content + `?lang=` variants serve identical HTML). This is acceptable because Hebrew pages exist for in-app/legal display, not Google discovery. If Hebrew *search* ever matters, it would require pre-rendered per-language URLs — which conflicts with the single-URL requirement. Don't "fix" it without that being a real goal.

## Search Console (manual, one-time)

1. Add the property `motify.uk` in [Google Search Console](https://search.google.com/search-console) (and optionally [Bing Webmaster Tools](https://www.bing.com/webmasters)).
2. Verify ownership — prefer the **DNS TXT** method at the domain registrar (no code change). Alternatively add `<meta name="google-site-verification" content="TOKEN">` to `templates/partials/head.html` and rebuild.
3. Submit `https://motify.uk/sitemap.xml`.
4. Watch Coverage + Performance; the sitemap stays current automatically on every build.

## Don't

- No `meta keywords`, no keyword stuffing, no doorway pages.
- Don't chase content-length targets or invest in ongoing content SEO unless web becomes a real acquisition channel.
