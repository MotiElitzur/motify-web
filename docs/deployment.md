# Deployment

**Purpose:** motify.uk is served by GitHub Pages straight from the committed static files — there is **no build step in the hosting path**. You build locally, commit the generated HTML, and push.

## Hosting

| | |
|---|---|
| Host | GitHub Pages |
| Repo | `github.com/MotiElitzur/motify-web` (remote `origin`) |
| Branch | `main` (Pages serves from it) |
| Domain | `motify.uk` (custom domain, pinned by `CNAME` → `motify.uk`) |
| Jekyll | disabled via empty `.nojekyll` |

**Why `.nojekyll` matters:** Jekyll (Pages' default) excludes dot-folders, which would drop `.well-known/`. The empty `.nojekyll` file turns Jekyll off entirely, so `.well-known/apple-app-site-association` and `assetlinks.json` are served as-is (see commit `f4a3007`).

## Build → commit → push flow

```bash
node build.mjs                     # regenerate all pages (zero deps)
git add -A                         # generated HTML + your source change together
git commit -m "…"
git push origin main               # GitHub Pages redeploys automatically
```

Because Pages serves the raw files, **the generated `*.html` must be committed** — a source-only commit ships nothing. Always regenerate before committing so the HTML matches the catalogs/templates. Generator details: [architecture.md](architecture.md).

## Deep-link infrastructure (hand-edited)

These files back the app's Universal Links / App Links and invite/download redirects. They are **not** generated by `build.mjs` — edit directly.

### `.well-known/` (association files)

- **`apple-app-site-association`** — iOS Universal Links. `appIDs: ["NYP8DXRMW6.moti.motify"]`, claims paths `/i/*` and `/go/*`.
- **`assetlinks.json`** — Android App Links. Package `moti.motify`, three signing SHA-256 fingerprints, `delegate_permission/common.handle_all_urls`.

Served correctly only because of `.nojekyll` (above). Keep the app IDs / fingerprints in step with the client's signing config.

### Redirect pages

| Path | Purpose |
|------|---------|
| `go/index.html` | "Get the app" — app-open-or-store redirect (`noindex`) |
| `i/index.html` | Invite/referral links (`/i/{code}`) — app-open-or-store, resolves the referral code (`noindex`) |

Both are claimed by the AASA `paths`, so on a device with the app installed the OS opens the app instead of the web page; otherwise the page bounces the visitor to the correct store. They are standalone HTML (inline styles on the app's azure palette), independent of the generated site.

## Other hand-edited files

`promote.html`, `analytics.html`, `404.html`, `ic_motify.svg` are committed as-is. `404.html` is GitHub Pages' custom not-found page. See the generated-vs-hand-edited table in [architecture.md](architecture.md) — do not run these through `build.mjs`.
